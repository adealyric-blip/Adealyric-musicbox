     4→// Design principle: Organization is the tenant root. Every domain table
     5→// carries an `organizationId`. Today there is exactly one Organization row
     6→// (your label/artist). Later, onboarding a second label or a solo indie
     7→// artist is just another row — no migration, no schema change, no rewrite.
     8→//
     9→// The ONE deliberate exception is the sync marketplace (SyncListing /
    10→// DealRoom), which is designed to cross tenant boundaries on purpose,
    11→// explicitly, and auditably — everything else stays strictly siloed.

   610→// ============================================================================
   611→// LEDGER — double-entry accounting, ledger-cli principles
   612→// ============================================================================
   613→// Every money-moving event (a DSP payout landing, a sync fee, a split
   614→// payout, a withdrawal) is a Transaction with two or more Entries whose
   615→// signed amounts sum to zero. Nothing ever mutates a "balance" column —
   616→// balance is always the sum of Entries for an Account, computed at read
   617→// time (or in a materialized view once volume demands it). This is the
   618→// same principle ledger-cli/hledger/beancount use: the ledger is an
   619→// immutable, append-only log; you never edit history, you post a
   620→// correcting entry.
   621→
   622→enum LedgerAccountType {
   623→  ASSET       // e.g. "Cash", "Royalties Receivable"
   624→  LIABILITY   // e.g. "Royalties Payable — Artist X"
   625→  EQUITY
   626→  REVENUE     // e.g. "Master Streaming Income", "Sync Fee Income"
   627→  EXPENSE     // e.g. "Distribution Fees", "Platform Commission"
   628→}
   629→
   630→/// The chart of accounts. Platform-level accounts (owner = PLATFORM) and
   631→/// per-participant payable accounts (owner = PARTICIPANT, ownerId =
   632→/// SplitParticipant.id) both live here, scoped to the org that owns the
   633→/// catalog the money relates to.
   634→model LedgerAccount {
   635→  id             String            @id @default(cuid())
   636→  organizationId String
   637→  code           String            // chart-of-accounts code, e.g. "2100-ROYALTIES-PAYABLE"
   638→  name           String
   639→  type           LedgerAccountType
   640→  ownerType      String            @default("PLATFORM") // PLATFORM | ARTIST | PARTICIPANT
   641→  ownerId        String?           // Artist.id or SplitParticipant.id when scoped to a person
   642→  currency       String            @default("USD")
   643→
   644→  organization Organization  @relation(fields: [organizationId], references: [id])
   645→  entries      LedgerEntry[] // filter by `direction` for "all debits" vs "all credits"
   646→
   647→  @@unique([organizationId, code])
   648→  @@index([organizationId])
   649→  @@index([ownerType, ownerId])
   650→}
   651→
   652→enum LedgerSourceType {
   653→  DSP_ROYALTY
   654→  SYNC_FEE
   655→  DIRECT_TO_FAN

   662→/// A Transaction is the atomic, balanced unit — it either has all its
   663→/// Entries or none of them (wrap the insert in a single db transaction at
   664→/// the application layer). sourceType + sourceId point back at whatever
   665→/// business event caused the posting (a RoyaltyStatement, a DealRoom, etc.)
   666→/// without a hard FK, since the source table varies.
   667→model LedgerTransaction {
   668→  id             String           @id @default(cuid())
   669→  organizationId String
   670→  date           DateTime         @default(now())
   671→  memo           String?
   672→  sourceType     LedgerSourceType
   673→  sourceId       String?
   674→

   705→// ============================================================================
   706→// Demucs, Matchering, and RVC are compute-heavy (GPU-friendly) and do NOT

   709→// container service — Modal, Replicate, Fly.io, or a self-hosted GPU box).

   711→// subscribe (Supabase Realtime) for job status instead of blocking.

   719→}

   768→  createdAt DateTime @default(now())
