     4→     4→// Design principle: Organization is the tenant root. Every domain table
     5→     5→// carries an `organizationId`. Today there is exactly one Organization row
     6→     6→// (your label/artist). Later, onboarding a second label or a solo indie
     7→     7→// artist is just another row — no migration, no schema change, no rewrite.
     8→     8→//
     9→     9→// The ONE deliberate exception is the sync marketplace (SyncListing /
    10→    10→// DealRoom), which is designed to cross tenant boundaries on purpose,
    11→    11→// explicitly, and auditably — everything else stays strictly siloed.

   611→   611→// LEDGER — double-entry accounting, ledger-cli principles
   612→   612→// ============================================================================
   613→   613→// Every money-moving event (a DSP payout landing, a sync fee, a split
   614→   614→// payout, a withdrawal) is a Transaction with two or more Entries whose
   615→   615→// signed amounts sum to zero. Nothing ever mutates a "balance" column —
   616→   616→// balance is always the sum of Entries for an Account, computed at read
   617→   617→// time (or in a materialized view once volume demands it). This is the
   618→   618→// same principle ledger-cli/hledger/beancount use: the ledger is an
   619→   619→// immutable, append-only log; you never edit history, you post a
   620→   620→// correcting entry.
   621→   621→
   622→   622→enum LedgerAccountType {
   623→   623→  ASSET       // e.g. "Cash", "Royalties Receivable"
   624→   624→  LIABILITY   // e.g. "Royalties Payable — Artist X"
   625→   625→  EQUITY
   626→   626→  REVENUE     // e.g. "Master Streaming Income", "Sync Fee Income"
   627→   627→  EXPENSE     // e.g. "Distribution Fees", "Platform Commission"
   628→   628→}
   629→   629→
   630→   630→/// The chart of accounts. Platform-level accounts (owner = PLATFORM) and
   631→   631→/// per-participant payable accounts (owner = PARTICIPANT, ownerId =
   632→   632→/// SplitParticipant.id) both live here, scoped to the org that owns the
   633→   633→/// catalog the money relates to.
   634→   634→model LedgerAccount {
   635→   635→  id             String            @id @default(cuid())
   636→   636→  organizationId String
   637→   637→  code           String            // chart-of-accounts code, e.g. "2100-ROYALTIES-PAYABLE"
   638→   638→  name           String
   639→   639→  type           LedgerAccountType
   640→   640→  ownerType      String            @default("PLATFORM") // PLATFORM | ARTIST | PARTICIPANT
   641→   641→  ownerId        String?           // Artist.id or SplitParticipant.id when scoped to a person
   642→   642→  currency       String            @default("USD")
   643→   643→
   644→   644→  organization Organization  @relation(fields: [organizationId], references: [id])
   645→   645→  entries      LedgerEntry[] // filter by `direction` for "all debits" vs "all credits"
   646→   646→
   647→   647→  @@unique([organizationId, code])
   648→   648→  @@index([organizationId])
   649→   649→  @@index([ownerType, ownerId])
   650→   650→}

   652→   652→enum LedgerSourceType {
   653→   653→  DSP_ROYALTY
   654→   654→  SYNC_FEE

   662→   662→/// A Transaction is the atomic, balanced unit — it either has all its
   663→   663→/// Entries or none of them (wrap the insert in a single db transaction at
   664→   664→/// the application layer). sourceType + sourceId point back at whatever
   665→   665→/// business event caused the posting (a RoyaltyStatement, a DealRoom, etc.)
   666→   666→/// without a hard FK, since the source table varies.

   670→   670→  date           DateTime         @default(now())
   671→   671→  memo           String?
   672→   672→  sourceType     LedgerSourceType
   673→   673→  sourceId       String?
   674→   674→
   675→   675→  organization Organization  @relation(fields: [organizationId], references: [id])
   676→   676→  entries      LedgerEntry[]
   677→   677→
   678→   678→  createdAt DateTime @default(now())
   679→   679→
   680→   680→  @@index([organizationId])
   681→   681→  @@index([sourceType, sourceId])
